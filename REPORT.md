# Agentic End-to-End Breakage Protocol Report

This report documents the issues found during testing of `synapse-cortex@beta`. The testing was done following the protocol provided. Due to `gh` cli being unauthenticated/unavailable, the bugs are documented below.

## Environment Log
- **OS:** Linux x86_64
- **Node:** v22.22.1
- **npm:** 11.11.0
- **synapse-cortex version:** 2026.5.5-beta.0
- **AI Client:** Custom MCP stdio client via `@modelcontextprotocol/sdk`
- **ripgrep available:** yes (`/usr/bin/rg`)

---

## Issues Found

### 1. [BUG] Phase 2: Memory Tools are missing entirely when SYNAPSE_MEMORY_ENABLED="true"
**Environment:**
- synapse-cortex version: 2026.5.5-beta.0

**Steps to Reproduce:**
1. Setup a custom MCP client using `@modelcontextprotocol/sdk`.
2. Connect to `synapse start` with environment variable `SYNAPSE_MEMORY_ENABLED="true"`.
3. List available tools.
4. Call `synapse_memory_manage` or `synapse_kg_query`.

**Expected Behavior:**
The memory and knowledge graph tools (`synapse_memory_manage`, `synapse_memory_query`, `synapse_kg_manage`, `synapse_kg_query`) should be available and should execute normally when `SYNAPSE_MEMORY_ENABLED` is set to `true`.

**Actual Behavior:**
The tools are not returned in `listTools` and calling them results in: `MCP error -32602: Tool synapse_memory_manage not found` (or `synapse_kg_query`, etc). None of the memory/kg tools seem to be registered or exported correctly to the MCP client.

**Severity:**
- [x] Silent wrong behavior / Core functionality failure

**Reproduction Rate:**
- [x] Always

### 2. [BUG] Phase 6: SQLite DB Corruption not detected
**Environment:**
- synapse-cortex version: 2026.5.5-beta.0

**Steps to Reproduce:**
1. Start synapse and ensure `.synapse/data/synapse.memory.db` is created.
2. Truncate the DB file to 0 bytes: `truncate -s 0 ~/.synapse/data/synapse.memory.db`.
3. Run `synapse doctor`.
4. Run `synapse start`.

**Expected Behavior:**
`synapse doctor` should flag the corrupted DB. The `synapse start` server should either attempt to recover, restore from backup, or crash cleanly with an error message about DB corruption.

**Actual Behavior:**
`synapse doctor` returns 10/10 OK, but reports: `OK schema_version: Schema version: 0 (unmigrated) (Database: /home/jules/.synapse/data/synapse.memory.db)`.
`synapse start` launches without errors, but silently fails to operate as expected.

**Severity:**
- [x] Silent wrong behavior / Data integrity issue

**Reproduction Rate:**
- [x] Always

### 5. [BUG] Phase 4: synapse_kg_query validation issues with entity_id vs start_entity_id
**Environment:**
- synapse-cortex version: 2026.5.5-beta.0

**Steps to Reproduce:**
1. Check `synapse_kg_query` inputs and validation requirements by trying to traverse: `{"action": "traverse", "start_entity_id": "proj_orion"}` vs `{"action": "traverse", "startEntityId": "proj_orion"}`.

**Expected Behavior:**
The schema and tool implementations should be consistent in snake_case or camelCase, or at least clearly documented.

**Actual Behavior:**
`startEntityId` is strictly required instead of `start_entity_id`. `entityId` is strictly required instead of `entity_id`. This goes against standard python/json naming conventions that might be generated by default and causes validation failures like `startEntityId is required`.

**Severity:**
- [x] UX issue

**Reproduction Rate:**
- [x] Always
